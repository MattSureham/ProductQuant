# Phase 0 Data Source Registry

This registry implements `PROJECT_SPEC.md` section 40 for the Phase 0 feasibility spike. It records observations and non-binding recommendations; it does not adopt a provider, dependency, licence, or external contract.

## Status vocabulary

- `RECOMMENDED — HISTORICAL ONLY`: usable for the stated narrow historical research purpose without implying a marketplace integration.
- `CONDITIONAL / BLOCKED`: technically interesting, but access, contract, retention, or authenticated-response evidence is still required.
- `DISCOVERY / FORWARD ONLY`: useful for discovery or newly accumulated snapshots, not historical reconstruction.
- `MANUAL VALIDATION ONLY`: acceptable for a small human-operated check, not an automated collector.
- `NOT SUITABLE`: fails a material v0.1 requirement under currently verified access and terms.

`Point-in-time` below means that the source can establish what was observable at factor time `t`, not merely return a present-day estimate about the past.

Certainty follows each linked evidence record: direct documentation/probe observations are `CONFIRMED`, analytical conclusions about reconstruction, terms compatibility, reliability, and suitability are `INFERRED`, and unresolved facts are repeated as `UNKNOWN`. Suitability labels are non-binding Phase 0 assessments, not provider adoption decisions.

## Registry conclusion

- **CONFIRMED:** No examined source currently supplies an accessible, authorised, reconstructable marketplace universe plus independent demand history.
- **INFERRED:** eBay Browse plus Feed is the least-bad forward marketplace candidate, but it remains blocked on production access and written confirmation that ProductQuant's archival and analytical use is permitted.
- **INFERRED:** The official Google Trends API alpha is the best strategic external-demand candidate. DataForSEO Google Trends Explore Standard is the most practical conditional probe, but neither currently proves strict point-in-time history.
- **CONFIRMED:** UCI Online Retail II is suitable for the first honest, narrow transaction-event backtest. It is not a substitute for the integrated ProductQuant demonstration required later by `PROJECT_SPEC.md` section 50.

All external entries become stale 30 days after the verification date or immediately when provider documentation, access status, pricing, licence terms, endpoint behaviour, or artifact digests change.
